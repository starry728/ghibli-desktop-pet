# 吉卜力台词「原声」自动获取可行性研究报告

> 全部结论基于本机 Node.js 实测。探测时间：本次会话。**未下载任何完整电影**，最大单次下载 409,600 字节。

## 0. 结论速览

| 子问题 | 结论 |
|---|---|
| 能否自动拿到这 40 句的原声？ | **不能全自动。** 卡在「拿到正片日语音轨」这一步，不是技术上做不到，而是没有合法且可自动化的片源 |
| B 站路线可行吗？ | **技术链路通了，内容不配合。** API 能拿到音频流并下载字节，但搜不到含台词的片段，且搜索接口风控严重 |
| 有现成台词音频站吗？ | **没有任何可达的站点提供吉卜力单句台词音频** |
| GitHub / 数据集有吗？ | **没有吉卜力音频数据集。** 有大量「工具」，但工具需要你自己提供片源 |
| **意外收获** | **官方日语字幕（SRT，含时间戳+说话人标注）完全可下载**，40 句里约 15 句能精确定位到 cue |

## 2. B 站路线（实测）

### 2.1 搜索接口：可用但风控极严

```
https://api.bilibili.com/x/web-interface/search/type?search_type=video&keyword=...
```

**但**：连续搜索约 2~3 次后必定被 ban，冷却 20 秒后仍需再等：

### 2.3 播放地址：✅ 免登录可用，且能下载字节

```
GET https://api.bilibili.com/x/player/playurl?bvid=BV1Pi421a7Cq&cid=1619483644&qn=80&fnval=16&fourk=1
→ {"code":0,"message":"OK"}
```
- `dash.audio` 3 条轨道，最佳：`id=30232  bw=91836  codecs=mp4a.40.2`（AAC-LC）
- `dash.video` 2 条轨道
- 带 `Range: bytes=0-262143` 下载：**`206 Partial Content`，实收 262,144 字节**，`content-type: video/mp4`，`brand=ftypisom`，`mp4a` box @461
- 另一例 `BV1TANv6dEnq`（cid=39965166936，14 个分 P）：`206`，262,144 字节，`brand=ftypiso5`

**DASH 音频是 fMP4 碎片流**（`ftyp` + `moof` + `mdat`，`esds@651`/`mp4a@615`），不是裸 AAC，**必须转码才能给桌面宠物播放**。

### 2.4 关键判断：用 B 站视频切 40 句台词现实吗？

**不现实。** 需要的东西按重要性排序：

1. **能搜到「正好包含这 40 句」的片段视频** —— 实测搜不到（见 2.2）
2. **搜索接口要能稳定批量调用** —— 实测 2~3 次就被 `-412` 封（见 2.1）
3. **逐句时间戳** —— ✅ 这个**能拿到**（见第 4 节，官方 SRT 字幕）
4. **说话人标注** —— ⚠️ 部分字幕有（`（ハウル）`），部分没有（千与千寻那版 0 条）
5. **正片完整片源** —— ❌ 这才是真正的死结

**并且**：即使全自动切好了，正片音频里**对白是和 BGM/音效混在一起的**，切出来的不是干净台词；很多台词还跨多个字幕 cue（如「ツォルド…」，需要合并相邻 cue）。

## 6. 最终结论

### 6.1 「能否自动拿到这 40 句的原声？」

**不能全自动。** 准确说法是：**技术链路的 4 个环节里，3 个已经打通，第 4 个卡死。**

| 环节 | 状态 | 证据 |
|---|---|---|
| 逐句时间戳 | ✅ **已解决** | kitsunekko 官方 SRT，5/7 部电影可下，15/40 句精确命中 |
| 说话人标注 | ⚠️ **部分解决** | 哈尔 126 条 / 波妞 326 条 / 天空之城 138 条 / 龙猫 42 条；**千与千寻 0 条** |
| 音频流抓取 + 切片 | ✅ **已解决** | playurl 免登录，`206` 实收 262,144 字节，可带 Range 截取任意区间 |
| **合法且可自动化的正片片源** | ❌ **卡死** | B 站搜不到台词片段（关键词匹配全失败）；搜索接口 2~3 次即 `-412`；`kaze`/`heron` 两部连字幕都没有 |

**额外的两个硬伤**：
1. **音质**：正片对白与 BGM/音效混录，切出来不是干净台词；很多台词跨多个字幕 cue，需要合并
2. **版权**：下载完整吉卜力电影的音轨，体积和版权都不该碰（本次已刻意只探测 262KB 样本）

**11/40 句（起风了 6 句 + 你想活出怎样的人生 5 句）连字幕都没有**，从源头就断了。

### 6.2 给用户的替代方案（按推荐度排序）

**① 用户自己提供音频文件 —— 最推荐，零版权风险，质量最好**

现有 `public/voice/<角色id>.mp3` 覆盖机制直接可用，用户可以从自己购买的 BD/DVD 里用 ffmpeg 截几句。这是唯一能同时拿到「干净原声 + 准确对应 + 无版权问题」的路子。
> 建议：我可以生成一份 40 行的「截取清单」（角色 id / 台词 / 电影 / 时间戳），用户在自购片源上按时间戳截取即可 —— 时间戳我这边已经能自动算出来。

**② 日语 TTS（Edge TTS `ja-JP`）—— 已跑通，最省事**

不是原声，但能立刻让 40 个角色都「说话」，且完全合法可批量。

**③ 名台词集视频 + 人工切片 —— 半自动**

我实测出的完整可复现链路（**注意：终点仍是人工**）：
```
1. 下载官方日语字幕（已验证 200）：
   https://kitsunekko.net/subtitles/japanese/<Film>/<file>.srt
2. 用第 4.3 节的脚本把 40 句匹配到 cue，拿到开始/结束时间戳
3. 片源：由用户提供自购 BD 抓取的 mkv
4. ffmpeg 切片（-ss/-to 按 cue 时间戳，-vn 抽音轨）
5. 人工试听校验（必需的，字幕 ≠ 音频内容）
```
**本机目前 `ffmpeg` / `ffprobe` / `yt-dlp` / `python` 全部缺失**（`python` 只是 Microsoft Store 的占位别名），走这条路需要先装 ffmpeg。

**④ B 站抓取 —— 不推荐**：内容搜不到、接口封得死、音轨是 fMP4 碎片流需转码、且有版权风险。
